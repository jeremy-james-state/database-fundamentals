Table work and row work are two families of verbs.

CREATE and ALTER and DROP change the object.

INSERT and UPDATE and DELETE change the facts inside it.

Mixing the families in your head is how DROP gets typed when DELETE was meant.

CREATE TABLE starts with the name, then a list of columns in parentheses.

Each column is a name, then a type.

Lines in that list are separated by commas.

The primary key is part of the contract, not a later wish.

You can mark a column PRIMARY KEY on its line, or name the key in a separate line.

Both mean: this value identifies the row, and it will not repeat.

Types on CREATE are promises about what a cell may hold.

A later INSERT that breaks the type is refused.

That refusal is the point of the type.

UPDATE names SET for the new value and WHERE for the rows that move.

Without WHERE, every row takes the new value.

Table management commands: CREATE, ALTER, DROP.

Data management commands: INSERT, UPDATE, DELETE, and SELECT to verify.

The lecture splits those families so you do not DROP when you meant DELETE.

CREATE needs a name and a column list and usually a key.
