The next skill is keeping only the rows you mean, and then counting them.

NULL is not a value you can compare with equals.

LIKE matches a pattern instead of an exact string.

Percent means any run of characters.

Patterns still live in quotes.

Once the rows are honest, you summarize.

COUNT star counts rows that survived the filter.

It does not count columns.

It counts surviving rows.

SUM adds a numeric column across those rows.

AVG takes the mean.

MIN and MAX find the edges.

Those functions collapse many rows into one number — unless you group.

GROUP BY collapses rows that share a value into one result row.

Group by city, and Austin becomes one row.

Denver becomes another.

Then COUNT tells you how many orders that city produced.

SUM tells you how much money that city produced.

The select list may only keep the grouped column and the summaries.

You cannot keep customer name unless you also group by it.

That rule is the engine protecting you from a fake fact.

HAVING filters groups after the grouping is done.

WHERE filters rows before the group.

That order is the whole trick.

If you filter cities after the count, you want HAVING.

If you filter rows before the count, you want WHERE.
