A foreign key is a column that says: this value already exists over there.

orders.customer_id is not a random number.

It is a promise that customers has that customer_id.

Without the promise, you can insert an order for customer ninety-nine.

Nobody named ninety-nine lives in customers.

The order is an orphan.

Reports that join the two tables will drop it, or invent a blank name.

The foreign key stops the orphan at the door.

Draw two boxes.

customers holds one row per person.

orders holds one row per purchase.

The arrow starts on orders.

It lands on customers.customer_id.

The many side holds the copy of the key.

The one side holds the original.

That direction is easy to get backwards.

You do not put order_id on customers.

One customer would then have room for only one order.

You put customer_id on orders, as many times as that person buys.

The parent table is the one whose primary key is copied.

The child table is the one that stores the copy.

Declare the foreign key when you create the child, or add it later with ALTER.

Related tables are tables that share a column on purpose, so a row over here can point at a row over there.

The shared column is not a coincidence of names.

It is a meaning: this review is about that product.

In the child table, the copy is the foreign key.
