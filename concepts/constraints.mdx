Constraints live in the [schema](/concepts/schemas). SQLite **checks them per row** on [INSERT](/reference/insert) and [UPDATE](/reference/update) — there is no separate “row constraint” syntax. What you choose is **where you write the rule**: on one [column](/concepts/tables#columns) or on the [table](/concepts/tables) as a whole.

## How constraints work

| Level | Written | Typical forms |
| --- | --- | --- |
| Column | On that column, after its [storage class](/concepts/storage-classes) | [NOT NULL](/reference/not-null), [UNIQUE](/reference/unique), [DEFAULT](/reference/default), [CHECK](/reference/check) |
| Table | After the column list | [PRIMARY KEY](/reference/primary-key), [FOREIGN KEY](/reference/foreign-key), multi-column `UNIQUE` / `CHECK` |
| Row (check time) | Not a syntax kind | Every constraint runs against each row the statement touches |

```sql
CREATE TABLE stations (
  id INTEGER,
  name TEXT NOT NULL UNIQUE,
  line TEXT,
  PRIMARY KEY (id)
);
```

`NOT NULL` and `UNIQUE` sit on `name`. `PRIMARY KEY (id)` sits at the table.

A primary key already forbids `NULL` on that key. You do not also need `NOT NULL` on `id`.

Some constraints have both placements. `id INTEGER PRIMARY KEY` is the column form of a single-column key. `PRIMARY KEY (id)` is the table form. A **composite** primary key (two or more columns) can only be a table constraint:

```sql
PRIMARY KEY (column_a, column_b)
```

`FOREIGN KEY (rider_id) REFERENCES riders (id)` is a table constraint. You can also write `REFERENCES riders (id)` on the `rider_id` column. SQLite still ignores the match until `PRAGMA foreign_keys = ON`.

A foreign key may be `NULL` unless you add `NOT NULL`. Missing parent is allowed; a *wrong* parent is not.

## Why databases use both

Table constraints express identity and relationships: which columns are the key, which columns point at another table. Column constraints express local rules: this value is required, unique, filled in, or from a closed set.

## When to use each

- **Table constraint**: [primary keys](/concepts/keys), [foreign keys](/concepts/keys), any rule that names more than one column
- **Column constraint**: a rule about one column only (`CHECK (fare != 0)`, `DEFAULT CURRENT_TIMESTAMP`)
- **Skip repeating `NOT NULL` on a primary key**: the key already requires a value
