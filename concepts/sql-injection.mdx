---
title: "SQL injection"
description: "SQL injection is when untrusted input is pasted into a statement string and runs as SQL."
keywords: ["CS50", "prepared statement", "injection", "security"]
---

If you build `SELECT … WHERE id = ` + user_text, an attacker can send `1 OR 1=1` or a `UNION` that reveals other tables. The DBMS cannot tell your query from theirs.

## How injection works

Unsafe pattern (do not use):

```sql
-- Pseudocode: string concatenation with user input
SELECT balance FROM accounts WHERE id = 1 UNION SELECT balance FROM accounts;
```

A **prepared statement** sends the SQL shape first, then binds values separately. The value is data, not syntax.

```sql
PREPARE balance_check FROM
  'SELECT balance FROM accounts WHERE id = ?';

SET @id = 1;
EXECUTE balance_check USING @id;
```

Even if `@id` contains text that looks like SQL, it is not executed as SQL.

## Why this matters

Injection is a common way to read or change data without permission. [GRANT](/reference/grant) limits accounts; prepared statements protect statement construction.

## When to use prepared statements

- **Any SQL that includes user or external input**
- **Skip string concatenation for values**: never assemble SQL text from the user
