**SQL** stands for Structured Query Language. *Structured* means a small set of reserved words in a fixed order. *Query* means you ask questions of data. The same language also creates, updates, and deletes rows.

Most relational DBMS products speak SQL. Each one supports a **dialect**: a subset or extension of the language. This site’s examples use SQLite unless a page says otherwise.

## Parts of the language

A statement is made of four kinds of token:

| Kind | What it is | Examples |
| --- | --- | --- |
| **Keyword** | A reserved word that tells the DBMS what to do | `SELECT`, `FROM`, `WHERE` |
| **Identifier** | A name you give a table or column | `books`, `title` |
| **Value** | Data: text, a number, or missing | `'hardcover'`, `2023`, `NULL` |
| **Function** | A name that takes input and returns a result | `AVG(rating)`, `COUNT(*)` |

```sql
SELECT title, author
FROM books
WHERE year = 2023
LIMIT 10;
```

In that statement, `SELECT`, `FROM`, `WHERE`, and `LIMIT` are keywords. `title`, `author`, `books`, and `year` are identifiers. `2023` and `10` are values.

## Keywords

A **keyword** is a word SQL already defines. You do not invent keywords. You choose among them.

Keywords sit in a fixed order. You do not put commas between keywords. You separate them with spaces or line breaks. Commas only separate items *inside* a list, such as columns after `SELECT`:

```sql
SELECT title, author
FROM books;
```

Write keywords in uppercase so they stand out from identifiers. SQLite accepts lowercase keywords. Uppercase is easier to read in a long statement.

## Identifiers and values

A bare word in a statement can look like a name or like data. Quotes tell the DBMS which you mean.

| | Identifier | Value |
| --- | --- | --- |
| **What it is** | A name you give a table or column | The data you compare or return |
| **Examples** | `books`, `title`, `year` | `'hardcover'`, `2023`, `NULL` |
| **Quotes in SQLite** | Double quotes if you quote it (`"books"`), or bare if the name is simple | Single quotes for text (`'hardcover'`); numbers stay unquoted; missing data is `NULL` |

`'title'` is the word title, not the `title` column. `"title"` (or bare `title`) is the column.

## (Aggregator) functions {#aggregator-functions}

These functions are often called **aggregates**. One turns many rows into one value. A ledger can list every amount, then one total at the bottom. `COUNT`, `AVG`, `MIN`, `MAX`, and `SUM` are that total: you no longer get one result row per book.

```sql
SELECT AVG(rating)
FROM books;
```

That result is not a `books` row. There is no `title` next to the average unless you ask a different question.

- `COUNT(*)` counts rows. `COUNT(column)` skips `NULL` in that column.
- `MIN` and `MAX` follow sort order. For text, that is A to Z, not shortest to longest.
- `AS` names a column. `DISTINCT` drops duplicates. Those can sit next to an aggregator, but they are not aggregators. `ROUND` is a [scalar](#scalar-functions).

## Scalar functions {#scalar-functions}

A **scalar** function takes values from one row and returns one value. It does not collapse the table. [trim](/reference/trim) strips leading and trailing whitespace. [upper](/reference/upper) and [lower](/reference/lower) change case. [ROUND](/reference/round) changes how a number looks.

You often `SET column = trim(column)` inside [UPDATE](/reference/update). The function result is not stored unless you write it back.

Practice on [update rows](/how-to/update-rows).

## When to use SQL

- **Talk to a DBMS**: read or change tables without editing files
- **The same question, repeated**: a query you can save and run again
- **A total over a set**: average, count, min, max, or sum
- **Skip it when**: you are still deciding what the table should contain; sketch the [table](/concepts/tables) first

## Common mix-ups

- **Keyword vs identifier**: `SELECT` is a keyword. `title` is an identifier (a column name).
- **Identifier vs string value**: `title` is the column. `'title'` is the word title.
- **`FROM` vs the file**: `FROM` names a table. The `.db` file is what you pass to `sqlite3`.
- **Aggregator vs row list**: an aggregator returns one value for the set, not one row per item.
- **Aggregator vs scalar**: `AVG` collapses rows. `trim` does not.
