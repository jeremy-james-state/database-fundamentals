## Syntax

SQL is a **language**, so it has **syntax**: rules for how you write valid commands.

**SQL** stands for **Structured Query Language**:

- **Structured** — [Tables](/concepts/tables) hold data in a fixed grid of rows and columns, with [cells](/concepts/tables#cells) holding [values](/concepts/tables#values). Statements use a small set of reserved words in a fixed order.
- **Query** — You ask the DBMS to retrieve data from tables.
- **Language** — The same words also create tables, update rows, and delete them.

You write those commands as clauses stacked into statements.

### Clause

A **clause** is the basic syntax unit: a reserved word or phrase in uppercase, then what follows — usually an [identifier](#identifier) (or a list of them), or for `WHERE` a **condition**.

```sql
SELECT title, author  -- clause = SELECT; identifiers = columns
FROM books            -- clause = FROM; identifier = table
WHERE year = 2023     -- clause = WHERE; condition
```

A clause is not a complete runnable command by itself. You stack clauses into a statement. Clauses sit in a fixed order. Do not put commas between clauses — commas only separate items *inside* a list, such as column identifiers after `SELECT`. Look up each clause under [Reference](/reference/select).

### Identifier

An **identifier** is a name you give a database object — usually a **table** or a **column** (`books`, `title`, `author`).

`SELECT` and `FROM` take identifiers (or a list of them). `WHERE` takes a **condition**, not an identifier.

Write identifiers in lowercase. For quotes and case, see [Conventions](#conventions). Names often map from [entities](/concepts/entities). The `.db` file goes to `sqlite3`, not after `FROM`.

#### Value {#values}

A **value** is the data in a [cell](/concepts/tables#cells) — what a column holds for a row: `'hardcover'`, `2023`, or `NULL`. Identifiers name columns and tables; values are the data in those cells. See [Values](/concepts/tables#values).

```sql
WHERE format = 'hardcover'   -- text: single quotes
WHERE year = 2023            -- number: no quotes
WHERE rating IS NULL         -- missing
```

`title` is a column identifier. `'title'` is text — a value. Quote kinds: [Conventions](#conventions).

### Statement

A **statement** is one or more clauses that form a complete command. You cannot have a statement without clauses. End it with `;`.

```sql
INSERT INTO books (title, year)
VALUES ('Kindred', 1979);
```

Two clauses. One statement. This writes a row — it is not a query.

Stack clauses into one command:

<Steps>
<Step>
```sql
SELECT title, author
```
</Step>
<Step>
```sql
FROM books
```
</Step>
<Step>
```sql
WHERE year = 2023
```
</Step>
<Step>
```sql
SELECT title, author
FROM books
WHERE year = 2023
```
</Step>
</Steps>

#### Families

A **statement family** is a named group of statements that do the same kind of work. Each statement is still built from clauses; the family names the job, not a clause.

For example, **DML** groups statements that change rows (`INSERT`, `UPDATE`, `DELETE`). **DDL** groups statements that shape the schema (`CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`).

Textbooks name either three families (**DDL**, **DML**, **DQL**) or five (those three plus **TCL** and **DCL**). The table uses five so you can map any acronym you meet. Only **DQL** is a query (it reads rows). The rest are statements that are not queries.

| Family | Stands for | Job | Typical statements |
| --- | --- | --- | --- |
| **DQL** | Data Query Language | Read rows | [`SELECT`](/reference/select), [`FROM`](/reference/from), [`WHERE`](/reference/where) |
| **DML** | Data Manipulation Language | Change rows | [`INSERT`](/reference/insert), [`UPDATE`](/reference/update), [`DELETE`](/reference/delete) |
| **DDL** | Data Definition Language | Shape the schema | [`CREATE TABLE`](/reference/create-table), [`ALTER TABLE`](/reference/alter-table), [`DROP TABLE`](/reference/drop-table) |
| **TCL** | Transaction Control Language | Bound a unit of work ([ACID](/concepts/transactions#acid)) | [`BEGIN`](/reference/begin), [`COMMIT`](/reference/commit), [`ROLLBACK`](/reference/rollback) |
| **DCL** | Data Control Language | Who may run statements | [`GRANT`](/reference/grant), [`REVOKE`](/reference/revoke) |

Practice with [select columns](/how-to/select-columns). Change rows with [insert](/how-to/insert-rows), [update](/how-to/update-rows), or [delete](/how-to/delete-rows). Shape tables with [create a table](/how-to/create-a-table). Combine result sets with [`UNION`](/reference/union), [`INTERSECT`](/reference/intersect), and [`EXCEPT`](/reference/except) — see [combine result sets](/how-to/combine-result-sets). Wrap related writes in [run a transaction](/how-to/run-a-transaction). On servers, [grant privileges](/how-to/grant-privileges).

### Query

A **query** is a statement that reads rows. It does not change the table. `SELECT` takes column identifiers; `FROM` takes a table identifier — see [Identifier](#identifier).

```sql
SELECT title, author
FROM books
WHERE year = 2023;
```

| Term | What it is | Example |
| --- | --- | --- |
| Statement | A complete runnable command | `INSERT INTO books (title, year) VALUES ('Kindred', 1979);` |
| Query | A statement that retrieves rows | `SELECT title, author FROM books WHERE year = 2023;` |

Every query is a statement. Not every statement is a query.

Next: [Select columns](/how-to/select-columns). Later: [JOIN](/how-to/join-tables) across [related](/concepts/relationships) tables, and `GROUP BY` to summarize.

### Conditions

`WHERE` keeps rows where a **condition** is true. A condition compares values; it is not an identifier by itself.

```sql
WHERE year = 2023
WHERE price > 10 AND in_stock = 1
WHERE title IS NOT NULL
```

Use `IS NULL` / `IS NOT NULL` for missing data — not `= NULL`. Practice on [filter rows](/how-to/filter-rows) and [match patterns](/how-to/match-patterns).

### Functions

In SQL, **function** often means a **scalar** function: one value in, one value out. It does not collapse rows.

An **aggregator** (aggregate) summarizes many rows into one value — `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`.

```sql
SELECT trim(title)        -- scalar: one title → one cleaned title
FROM books;

SELECT COUNT(*)           -- aggregator: many rows → one number
FROM books;
```

Practice aggregators on [summarize rows](/how-to/summarize-rows). Practice scalars when you [update rows](/how-to/update-rows).

`AS` names (aliases) a column or expression result — `trim(title) AS clean_title`, `COUNT(*) AS book_count`. Use it when you rename something after manipulation, scalar or aggregator. It is not unique to aggregator functions.

### Conventions

Once you know clauses, statements, and queries, write statements this way:

| Convention | Rule | Example |
| --- | --- | --- |
| Uppercase clauses | Put the reserved words that open clauses in uppercase. | `SELECT` · `FROM` · `WHERE` |
| Lowercase identifiers | Write table and column names in lowercase. | `books` · `title` · `author` |
| Quote kinds | Double-quote identifiers when you quote them; single-quote string values. | `"title"` vs `'Kindred'` |
| One clause per line | Put each clause on its own line. | `SELECT title`<br />`FROM books`<br />`WHERE year = 2023` |
| Semicolon | End the statement with `;`. | `SELECT title FROM books;` |

### Common mix-ups

- **Query vs statement**: every query is a statement. Not every statement is a query. A query reads data (`SELECT` / DQL). DML, DDL, TCL, and DCL are statements that are not queries.
- **Clause vs statement**: a clause is a reserved word/phrase plus what follows (identifiers or a condition) — not runnable alone. A statement stacks one or more clauses and ends with `;`.
- **DDL vs DML**: DDL changes the schema. DML changes rows. `SELECT` is DQL (a query), not DML.
- **Three families vs five**: some books list only DDL, DML, and DQL. TCL (transactions) and DCL (privileges) are the usual extras.
- **Reserved word vs identifier**: `SELECT` is a reserved word that opens a clause. `title` is an identifier (a column name).
- **Identifier vs condition**: `SELECT` / `FROM` take identifiers. `WHERE` takes a condition.
- **Identifier vs string value**: `title` or `"title"` names the column. `'title'` is the word title.
- **`FROM` vs the file**: `FROM` names a table. The `.db` file is what you pass to `sqlite3`.
- **Aggregator vs row list**: an aggregator returns one value for the set, not one row per item.
- **Aggregator vs scalar**: `AVG` collapses rows. `trim` does not.

### Dialect

Most relational DBMS products speak SQL. Each one supports a **dialect**: a subset or extension of the language. This site’s examples use SQLite unless a page says otherwise.

### Declarative and set-based

SQL is **declarative**: you describe *what* result you want. The engine chooses *how* to produce it. It is also **set-based**: one statement acts on a whole [set of rows](/concepts/tables#tables-as-sets), not a procedural loop that visits one row at a time.

### Aggregator functions

These functions are often called **aggregates**. One turns many rows into one value. A ledger can list every amount, then one total at the bottom. `COUNT`, `AVG`, `MIN`, `MAX`, and `SUM` are that total: you no longer get one result row per book.

```sql
SELECT AVG(rating)
FROM books;
```

That result is not a `books` row. There is no `title` next to the average unless you ask a different question.

- `COUNT(*)` counts rows. `COUNT(column)` skips `NULL` in that column.
- `MIN` and `MAX` follow sort order. For text, that is A to Z, not shortest to longest.
- `DISTINCT` drops duplicates. It can sit next to an aggregator, but it is not an aggregator. `ROUND` is a scalar function.

Practice on [summarize rows](/how-to/summarize-rows). Look up each function under Summarize in Reference, starting with [COUNT](/reference/count).

### Scalar functions

A **scalar** function takes values from one row and returns one value. It does not collapse the table. [trim](/reference/trim) strips leading and trailing whitespace. [upper](/reference/upper) and [lower](/reference/lower) change case. [ROUND](/reference/round) changes how a number looks.

You often `SET column = trim(column)` inside [UPDATE](/reference/update). The function result is not stored unless you write it back.

Practice on [update rows](/how-to/update-rows).
