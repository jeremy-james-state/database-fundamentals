Five **storage classes** apply to values: `NULL`, `INTEGER`, `REAL`, `TEXT`, and `BLOB` (binary large object: bytes as given, for example an image).

A column does not lock to one class. It has an **affinity**. SQLite tries to convert an insert toward that affinity when it can.

## How storage classes and affinities work

| Affinity | What the column prefers |
| --- | --- |
| `TEXT` | Characters. Inserting `10` stores `'10'`. |
| `INTEGER` | Whole numbers. Inserting `'10'` stores `10`. |
| `REAL` | Floating-point numbers. |
| `NUMERIC` | Integer or real, whichever fits. Default if you omit a type. Useful for timestamps and amounts. |
| `BLOB` | Leave the bytes unchanged. |

`INTEGER` vs `REAL` vs `NUMERIC` feel similar because they overlap. **INTEGER** wants whole numbers. **REAL** wants decimals. **NUMERIC** will take either. Pick INTEGER when you need exact whole-number math (store cents as `10`, not `'$0.10'` as text). Pick REAL when a decimal is the fact. Pick NUMERIC when the column might be either, or a date-time.

SQLite has no boolean type. Use `INTEGER` `0`/`1`, or `TEXT`, and a [CHECK](/reference/check) if the set of values is closed.

## Why databases use types

You cannot total fares stored as `'$0.10'`. Text is not a number. Affinity is SQLite’s way of nudging values toward a class without a rigid type system. [MySQL and PostgreSQL](/concepts/server-types) declare a type on the column (`VARCHAR`, `INT`, `DECIMAL`) and reject values that do not fit.

## When to use each class

- **INTEGER**: counts, invented ids, money in cents
- **REAL**: measurements that are truly decimal
- **TEXT**: names, codes, `'enter'` / `'exit'`
- **BLOB**: files you must not reinterpret
- **NULL**: missing
- **Skip mixing money as text**: strip the `$` before you store it
