A table is **structured** data: items down, attributes across, one value in each cell. That fixed grid is why [SQL](/concepts/sql) is *Structured* Query Language — the language assumes rows, columns, and values in known places. You already know the shape from paper lists and spreadsheets.

In design terms, the table is the physical form of an [entity](/concepts/entities) — attributes become columns, instances become rows, and the unique identifier becomes the [primary key](/concepts/keys).

## How a table works

Take a `books` table:

| title | author | year |
| --- | --- | --- |
| The Left Hand of Darkness | Ursula K. Le Guin | 1969 |
| Kindred | Octavia E. Butler | 1979 |

### Rows

A <Tooltip tip="One item in the table">row</Tooltip> is one item. In `books`, each row is one book. Add a book with a new row.

### Columns

A <Tooltip tip="One attribute of every item">column</Tooltip> is one kind of fact about every item: `title`, `author`, `year`. Add a fact about every book with a new column.

### Cells

Where a row and a column meet is a <Tooltip tip="The intersection of one row and one column">cell</Tooltip>. In `books`, Kindred’s `year` is one cell.

### Values

The data in that cell is a <Tooltip tip="The data stored in one cell">value</Tooltip>. Kindred’s year cell holds `1979`.

That value is the attribute on that instance — the year of that book. In SQL, [values](/concepts/sql#values) are also what you compare and return.

## Tables as sets

A <Tooltip tip="An unordered collection of unique elements">set</Tooltip> is an unordered collection of unique elements. Codd’s relational model builds on that idea: a table is a set of rows under one [schema](/concepts/schemas) — the same columns for every row.

Row order is arbitrary unless you ask for it with [`ORDER BY`](/reference/order-by). Uniqueness is a [primary key](/concepts/keys) rule and part of first normal form — see [normalization](/concepts/normalization).

SQL works on whole collections of rows: keep rows with [`WHERE`](/reference/where), summarize with [`GROUP BY`](/reference/group-by), combine result sets with [`UNION`](/reference/union), [`INTERSECT`](/reference/intersect), and [`EXCEPT`](/reference/except). Matching every row of one table to every row of another is a Cartesian product — a building block for joins, rarely the answer you want alone.
