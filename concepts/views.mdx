---

You write a `SELECT`, then save it with [CREATE VIEW](/reference/create-view). Every time you query the view, SQLite runs that query again against the underlying tables.

## How a view works

```sql
CREATE VIEW author_titles AS
SELECT authors.name, books.title
FROM authors
JOIN authored ON authored.author_id = authors.id
JOIN books ON books.id = authored.book_id;
```

`SELECT * FROM author_titles;` reads like a table. The rows still live in `authors`, `authored`, and `books`.

| Kind | How long it lasts | How you define it |
| --- | --- | --- |
| **View** | Until you [DROP VIEW](/reference/drop-view); stored in the schema | `CREATE VIEW name AS …` |
| **Temporary view** | Until you close the SQLite connection | `CREATE TEMPORARY VIEW name AS …` |
| **CTE** (common table expression) | For one statement only | `WITH name AS (…)` before the main `SELECT` |

Yes: **`WITH` starts a CTE**. A comma after one CTE’s `)` lets you define another CTE in the same statement.

Views are efficient for computed results (averages, joins) because you keep the detail rows and recompute when you query. You do not store a second copy of every average.

You cannot always `UPDATE` or `DELETE` a view directly. Change the underlying table, or use an [INSTEAD OF](/how-to/write-through-a-view) trigger.

## Why databases use views

- **Simplify**: many tables look like one
- **Aggregate**: store the *query* for averages, not only the totals
- **Partition**: one view per slice (`WHERE year = 2022`)
- **Secure**: omit or replace sensitive columns before you share access

## When to use each kind

- **View**: the shape is useful for everyone and belongs in `.schema`
- **Temporary view**: you are exploring and do not want it saved
- **CTE**: you need a named subquery once, inside this statement
- **Skip a permanent view when**: the query is a one-off; use a CTE or a bare `SELECT`

## Related ideas

[Soft deletion](/concepts/soft-deletion) pairs well with a “current rows” view. [Triggers](/concepts/triggers) can run **INSTEAD OF** writes on a view.

## Common mix-ups

- **View vs table**: a table stores rows. A view stores a query.
- **Temporary view vs CTE**: temporary lasts the connection. A CTE lasts one statement.
- **`WITH` vs `CREATE VIEW`**: `WITH` is not a view in the schema. It is only a CTE for that query.
