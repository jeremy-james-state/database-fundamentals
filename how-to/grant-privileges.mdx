Least privilege: a reporting user may `SELECT` but not `DROP`.

Authentication proves which account connected. Authorization determines what that account may do. A privilege such as `INSERT` permits the account to attempt a write; [constraints](/concepts/constraints) still reject invalid values and broken relationships.

| Layer | Example responsibility |
| --- | --- |
| Authentication | Verify that the connection belongs to `analyst` |
| Authorization | Permit `SELECT`; deny `DROP` |
| Integrity | Reject an invalid foreign key or failed `CHECK` |

Do not use constraints as permissions, and do not use permissions as data validation. Apply both.

## Prerequisites

- A MySQL admin session ([connect to MySQL](/how-to/connect-to-mysql))
- A user account to grant to

## Grant and revoke

<Steps>
  <Step title="Grant">
    ```sql
    GRANT SELECT, INSERT
    ON transit.*
    TO 'analyst'@'localhost';
    ```
  </Step>
  <Step title="Revoke">
    ```sql
    REVOKE INSERT
    ON transit.*
    FROM 'analyst'@'localhost';
    ```
  </Step>
</Steps>

## Verify the result

You succeeded when the analyst can `SELECT` and cannot run a revoked privilege.

## Troubleshooting

- **Access denied after GRANT**: user must reconnect; host (`'user'@'%'`) must match how they connect.
- **Still too powerful**: grant on specific tables, not `*.*`
