---
title: "Group rows"
description: "Collapse rows that share a key, then filter those groups with HAVING."
---

`WHERE` filters rows **before** the group. `HAVING` filters **after** the aggregator runs.

## Prerequisites

- An aggregator ([SQL](/concepts/sql#aggregator-functions))
- A `ratings` table with `book_id` and `stars`

## Group, then filter groups

<Steps>
  <Step title="Average per book">
    [GROUP BY](/reference/group-by) one column. Each distinct `book_id` becomes one result row.

    ```sql
    SELECT book_id, ROUND(AVG(stars), 2) AS average_rating
    FROM ratings
    GROUP BY book_id;
    ```
  </Step>
  <Step title="Keep groups that meet a condition">
    [HAVING](/reference/having) uses the aggregator. `WHERE average_rating >= 4` fails: that column does not exist yet.

    ```sql
    SELECT book_id, ROUND(AVG(stars), 2) AS average_rating
    FROM ratings
    GROUP BY book_id
    HAVING AVG(stars) >= 4.0;
    ```
  </Step>
  <Step title="Sort the groups">
    ```sql
    SELECT book_id, ROUND(AVG(stars), 2) AS average_rating
    FROM ratings
    GROUP BY book_id
    HAVING AVG(stars) >= 4.0
    ORDER BY average_rating DESC;
    ```
  </Step>
</Steps>

## Verify the result

You succeeded when you get one row per `book_id`, not one row per rating, and only groups that pass `HAVING`.

## Troubleshooting

- **`WHERE` on an average**: move the test to `HAVING`.
- **Extra columns in `SELECT`**: every non-aggregated column belongs in `GROUP BY`.
