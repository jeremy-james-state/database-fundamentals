When you finish, you can turn a short interview into a first model, write a `schema.sql`, apply it, and change a table without starting from a spreadsheet.

## Prerequisites

- SQLite ([open a SQLite database](/how-to/open-a-database))
- [Normalization](/concepts/normalization) and [keys](/concepts/keys)
- About 25 minutes

<Info>
Examples use SQLite. End every SQL statement with a semicolon. Use a new file such as `transit.db` so you do not overwrite lesson data.
</Info>

## Step 1: Extract a first model from language

Before you write SQL, turn the interview language into a candidate model. Underline the **nouns** and circle the **verbs**:

> “A station has a name and a line. A rider has a name. A rider visits a station. Each visit records a type, time, and fare.”

Use two patterns:

- **Possession verbs** such as _has_ or _owns_: the possessor noun is a candidate [entity](/concepts/entities); the possessed detail is a candidate [attribute](/concepts/attributes).
- **Action verbs** between two entity nouns: the action is a candidate [relationship](/concepts/relationships).

| Interview phrase | First model |
| --- | --- |
| “A station has a name and a line” | `stations` entity with `name` and `line` attributes |
| “A rider has a name” | `riders` entity with a `name` attribute |
| “A rider visits a station” | relationship between `riders` and `stations` |
| “Each visit records a type, time, and fare” | `visits` relationship table with its own attributes |

### Turn action verbs into draft relationship lines

For each useful subject–verb–object sentence in the transcript:

1. **Extract the sentence.** Mark the subject noun, action verb, and object noun.
2. **Test both nouns.** If each noun needs its own identity, attributes, or relationships, keep both as entities.
3. **Draw a candidate line.** Connect the entity boxes and label the line with the action verb. “A rider visits a station” becomes a `visits` relationship between `riders` and `stations`.
4. **Validate the meaning.** Review the draft with stakeholders before you choose keys or tables.
5. **Ask for cardinality.** The verb alone does not tell you the minimum or maximum count. Ask whether each side is optional or required, and whether it permits one or many matches.

### Show the verb in ER notation

The same relationship appears differently depending on the notation:

- **Crow’s Foot notation** connects two entity boxes with a line. You may label the line with the verb; symbols at each end show minimum and maximum cardinality.
- **Chen notation** places the relationship verb inside a diamond between the two entity rectangles.

The verb tells you what the entities do together. The symbols come from separate business rules about whether participation is optional or required and whether each side allows one or many matches. See [Entity-Relationship Diagrams](/concepts/entity-relationship-diagrams) for the notation itself.

<Warning>
  Grammar gives you candidates, not a finished schema. A noun may be an attribute in one system and an entity in another. A verb reveals a possible relationship, but not its cardinality. Ask follow-up questions: How many? Is it required? Can it repeat? Must you keep its history?
</Warning>

## Step 2: Create tables with types

```sql
CREATE TABLE stations (
  id INTEGER,
  name TEXT,
  line TEXT
);

CREATE TABLE riders (
  id INTEGER,
  name TEXT
);

CREATE TABLE visits (
  rider_id INTEGER,
  station_id INTEGER,
  type TEXT,
  datetime NUMERIC,
  fare NUMERIC
);
```

You are on track when `.tables` lists all three.

## Step 3: Recreate with constraints

Drop the empty tables, then add keys and column rules:

```sql
DROP TABLE visits;
DROP TABLE riders;
DROP TABLE stations;

CREATE TABLE stations (
  id INTEGER,
  name TEXT NOT NULL UNIQUE,
  line TEXT,
  PRIMARY KEY (id)
);

CREATE TABLE riders (
  id INTEGER,
  name TEXT,
  PRIMARY KEY (id)
);

CREATE TABLE visits (
  id INTEGER,
  rider_id INTEGER,
  station_id INTEGER,
  type TEXT CHECK (type IN ('enter', 'exit')),
  datetime NUMERIC DEFAULT CURRENT_TIMESTAMP,
  fare NUMERIC CHECK (fare != 0),
  PRIMARY KEY (id),
  FOREIGN KEY (rider_id) REFERENCES riders (id),
  FOREIGN KEY (station_id) REFERENCES stations (id)
);
```

Turn foreign keys on in this session:

```sql
PRAGMA foreign_keys = ON;
```

## Step 4: Alter a column

```sql
ALTER TABLE visits
ADD COLUMN duration INTEGER;
```

`.schema visits` should list `duration`.

## Step 5: Save and apply a file

Copy the `CREATE TABLE` statements into `schema.sql`. In a new empty database:

```text
sqlite> .read schema.sql
```

From the shell, the same file is:

```bash
sqlite3 transit.db < schema.sql
```
